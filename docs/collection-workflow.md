# Collection workflow

This is an initial description of Kinefoundry's proposed pilot workflow. Deliverables and acceptance criteria are agreed with each buyer.

## 1. Define the brief

Specify the task, environment, intended model use, capture modality, coverage targets, output schema, and acceptance criteria. Confirm location and data-origin requirements before collection.

## 2. Check a small sample

Validate visibility, timing, metadata, labels, and import compatibility with the buyer's technical reviewer before increasing volume. Human video does not contain robot actions or joint states; the capture modality must provide the signals the model needs.

## 3. Organize collection

Arrange suitable sites, demonstrators, equipment, permissions, and safe operating procedures. Use a consistent collection protocol and record deviations.

## 4. Review and correct

Review recordings against the agreed criteria. Record the reason for rejection, request recapture when useful, and track coverage gaps. Keep quality decisions and rights checks separate so a technically usable recording cannot bypass a permission hold.

## 5. Prepare delivery

Package accepted recordings with metadata, provenance, documented usage rights, and a delivery manifest. Validate the export against the agreed format. Dataset acceptance alone does not demonstrate an improvement in model performance.

## Capture options

Depending on the task, a pilot may use first-person or multi-angle video, depth cameras, hand and body tracking, or robot demonstrations through compatible third-party systems. Hardware availability, calibration, synchronization, integration, and safety requirements are confirmed per pilot.
